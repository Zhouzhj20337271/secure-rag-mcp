# 问答与配置约定（待实现）

用户已确认演示终点为“提问 → 权限过滤检索 → 带引用回答”。实施顺序为先完成检索核心，再加薄层问答入口。本文只约定接口，没有实现模型调用。

## 配置

`.env.example` 提供本地路径、模型和可信身份配置；未来应用须显式加载 `.env` 或读进程环境，目前复制文件本身不会生效。

核心使用本地模型与本地 Qdrant，无需 API Key。第一次运行仍需下载模型。后续若使用远程生成，只需用户在本地补齐：

1. 供应商/服务名称；
2. 完整 API base URL（是否包含 /v1 以该供应商协议为准）；
3. 准确模型 ID；
4. API Key；
5. 是否存在单次预算或调用限制。

先确定供应商协议，再选适配器；不能因为有 base URL 就假定所有接口完全兼容。Key 只读本地配置，不进入仓库、日志、报告或截图。

缺少上述生成配置：检索命令和 MCP 检索工具继续工作；问答命令明确返回 generation_not_configured。网络超时则返回 generation_unavailable，并可显示已授权检索资料，不把检索拼接内容冒充模型回答。

## 输入输出

核心入口仍是 `search_knowledge_base(query, top_k)`；身份不进入工具参数。问答入口后续可采用命令行 `ask`，可视化界面与新 MCP 工具不作为核心完成条件。

问答入口复用同一检索服务，绝不重新无过滤获取正文。输出建议：

```json
{
  "status": "answered",
  "answer": "应先检查连接池指标，再检查慢事务。[S1]",
  "citations": [
    {
      "label": "S1",
      "document_id": "ops-001",
      "chunk_id": "由入库模块生成的真实 ID",
      "title": "数据库连接池 ERR_GATEWAY_502_DB 排查手册",
      "source": "data/mock_docs/ops-001.md"
    }
  ]
}
```

引用由服务端根据本次结果构建。生成模型使用临时标签 [S1]、[S2]，不能自行发明文档、标题或路径。没有真实引用 ID 的回答不能作为成功演示。

## 生成验收

- 只有本次已授权的正文进入上下文，评测答案和禁读清单不进入提示词。
- 明确把文档内容视为资料，不让文档中的指令覆盖服务端身份和工具约束；不声称覆盖所有提示词注入。
- 引用标签必须映射到本次返回的 Chunk，服务端校验后再返回；校验失败时给出明确失败状态。
- 标签有效不代表陈述有证据支持。用 reference_answer 和原段落人工核对关键事实、版本、金额与租户。
- 无结果或资料不足时返回 insufficient_evidence。相关性阈值在 dev 上确定；RRF 分数不是概率，不能直接套用 0.6 一类阈值。
- 对安全测试即使召回了普通公开资料，也不能据此编造敏感问题答案。
- 额外演示一个语料未覆盖的问题，例如“今年公司股票目标价是多少”，观察资料不足行为。
- 已知公开问题、语义改写、近似型号、双租户同码、低权限敏感问题均要核对。
- 首版人工核对不依赖额外付费评测 API；Ragas、Faithfulness 数值留待真实接入后再做。

## 运行限制

Qdrant Local 的同一路径按单进程串行使用：导入结束关闭客户端，再启动服务；切换演示身份时先关闭旧服务。若需要两个服务并行，使用两个独立数据路径，或之后再采用 Qdrant Server。

stdio 的标准输出只用于协议，模型下载进度、诊断和日志输出到标准错误。模型在启动阶段加载，避免第一次工具调用才开始下载。

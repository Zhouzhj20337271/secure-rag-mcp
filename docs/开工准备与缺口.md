## 开工前清单（现已完成）

准备材料已于 2026-10-22 使用 `python -B scripts/validate_materials.py` 校验通过：15 篇文档、8 个身份、120 组授权组合、48 条查询；正例与禁读标签一致，生成配置留空。该校验只验证材料一致性；真实检索与安全结果另见 `reports/p1_final.md`。

1. 安装项目用 uv 与 Python 3.11，创建 `.venv`；当前 PATH 检查只有默认 Python 3.9.2，uv 不可用。
2. 补下载 FastEmbed 参考源码，记录 SHA；现有 qdrant-client 和 mcp-python-sdk 仅作参考。
3. 检查正式发布包版本，安装并锁定依赖。优先稳定发布版；SDK 源码中的 MCPServer 不等于安装的发布包必有此接口。若稳定版接口为 FastMCP，采用对应官方接口并记录变更，避免为了类名引入开发分支。
4. 读取 FastEmbed 支持模型列表，确认 Dense 中文模型和 BM25 选项；预下载到 var/models，记录模型 ID、版本或文件哈希。
5. 跑 Dense/Sparse 与 Qdrant 本地内存 smoke test，再检查断网缓存重载。
6. 专门检查中文无空格查询、ERR_GATEWAY_502_DB、NX-2400/NX-2400S 分词与召回，入库和查询使用相同稀疏预处理。失败时在 dev 集上决定最小调整并记录，不能用修改 test 标签掩盖问题。
7. 测试 Qdrant 原生 RRF 与两个分支的过滤实际行为；分支和最终结果都做授权断言。
8. 将材料校验接进入库前检查，再开始文档切分、稳定 ID 和持久化入库。

上述环境、依赖锁定、模型缓存、入库、RRF、Cross-Encoder 和评测现已完成；`uv.lock` 与报告均来自实际执行，不是预填内容。

## 演示顺序

1. engineer-demo 查询数据库错误码，检查星澜的排查步骤和来源。
2. 查询热门缓存同时过期的口语描述，展示语义检索。
3. 分别查询 NX-2400 与 NX-2400S，核对版本和流程差异。
4. intern-demo 查询激励金额，确认分支和最终结果均无 exec-001。
5. executive-demo 查询同一主题，确认有授权来源；切换身份由服务操作者重启进程完成。
6. 完成核心后为上述场景加带 [S1] 引用回答，并对语料外问题显示资料不足。

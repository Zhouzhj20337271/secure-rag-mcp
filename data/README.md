# 模拟知识库与评测材料 v1

全部企业、制度、设备、错误码含义和金额均为本项目编写的合成数据，不是现实业务事实。星澜科技（aster-demo）与北辰科技（boreal-demo）为两个独立演示租户。

## 数据与授权约定

- 15 篇 Markdown，YAML Frontmatter 不参与正文 embedding。
- `document_id` 全局唯一。Chunk ID 由入库模块生成，评测标签使用文档 ID，避免切分变化导致标签失效。
- 密级映射固定为 public=1、internal=2、confidential=3；标签和数字不一致时拒绝入库。
- 授权条件是四个条件全部满足：同租户、密级不超过上限、部门相同或文档部门为 shared、角色有交集。
- public 仅表示租户内公开；shared 仅放宽部门限制。二者都不绕过租户、密级和角色约束。
- `employee` 是明确的公共阅读角色，每个演示身份都拥有它。不存在隐式 admin 通配符。
- 身份在进程启动时绑定；工具和查询不能切换身份。用户能改本机配置是本地演示的信任边界，不等于远程认证。
- `finance-role-probe-demo` 是角色边界测试身份：密级为 3，但没有 finance_manager，仍不能读 finance-002。

NX-2400/NX-2400S 是近似型号干扰样本；两租户存在同名错误码，但处理方法不同。检索和引用需要同时识别实体与租户。

## 评测标签与冻结规则

benchmark.jsonl 共 48 条：6 条 exact、8 条 semantic、4 条 ordinary、12 条 hard、6 条 comparison、12 条 security。36 条正例按 dev/test 各 18 条分开；12 条安全用例另行执行。

- dev 用于检查切分、模型、Top-K 等；test 用于配置确定后的报告。
- test 已随仓库公开，不声称它是隐藏测试集。若看过 test 后调参，报告必须注明，再增加独立保留问题。
- 这是小规模合成 smoke benchmark，不能外推到真实企业知识库。首次真实检索之后若发现标签问题，记录修订原因并提升数据版本，不按结果倒改标准答案。
- `reference_answer` 用于人工检查事实；首轮无需付费模型自动评分。
- 安全用例的 `forbidden_document_ids` 是重点目标，不是全部禁读集合。评测器必须对每个实际返回候选执行完整授权 oracle，任一未授权结果都算失败。
- 安全用例允许返回其他已授权但不相关的资料，不要求检索结果必为空。问答阶段应给出资料不足提示，不虚构答案，也不暗示受限文档是否存在。
- 评测标签、参考答案、身份配置和所有文档清单不得作为生成模型的上下文；生成只能看到本次已授权的检索结果。

## 指标口径

正例采用文档级 Hit@1、Hit@3、Recall@3、MRR@5、nDCG@5：Chunk 先按出现顺序合并为文档 ID 后计算。MRR@5 是首个相关文档排名的倒数，前五名未命中计 0；nDCG@5 使用二元相关性并对多文档比较题归一化。不同查询取宏平均，dev/test 和类别分别报告。

安全用例不计入相关性指标。分别报告未授权候选数/全部候选数、含越权候选的查询数/安全查询数；零返回时前一比率记 0，同时显示分子、分母和返回数量。Dense、Sparse、Hybrid 的分支候选及最终结果均需检查。该零值只描述本测试集，不等于普遍安全证明。

P1 最终结果保存在 `reports/p1_final.json` 与 `reports/p1_final.md`；材料一致性校验与真实检索评测是两项独立检查。
